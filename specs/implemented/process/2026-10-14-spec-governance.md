# 契约编写、生命周期与结构检查规范决策

Status: implemented
Date: 2026-10-14
Record-Format: structured

## 背景

现有注册表定义了目录与 header，但没有完整正文模板；implemented 同时承载
“已采纳”与“已交付”的表达。历史决策存在坏链接、后续状态追加与替代链缺失，
未采纳家族的详细设计分散在现行叶契约中。使用者已明确要求实施规范落地。

## 决策

- `specs/README.md` 唯一拥有编写规则、生命周期、三类模板和变更流程。
- implemented 表示采纳生效，proposed 表示未采纳；代码实现、构建与验收事实由
  实施资料记录，不由目录状态推断。未采纳提案不因本轮格式整理被自动采纳。
- 根、叶按固定顶层结构归组；原有数字节号和条款标识保留为下级定位。
- 场景工具 schema、技能身份及配置归场景提案 §11–§12；跟踪的宿主、目录、
  连续资源、装配与站端消费约定归跟踪提案 §8–§12。现行契约只留提案指针。
- 新增只读结构入口，人工继续判断语义、唯一归属及实现真实性；本轮不执行检查。

## 理由与放弃的选项

将规范状态与交付事实分开，可以让正确要求约束尚未跟上的实现，并避免把未验收
代码当作已证明能力。只靠标题和目录无法保证条款完整，因此同时规定模板和写法。

不新增第二份治理根契约或项目模板子树，避免规则重复归属；不重编号所有业务条款，
避免已有引用失效；不把冻结历史强行改写成新模板，避免抹掉当时决策依据。

## 影响

2026-10-14 之前的决策使用 historical 结构例外，补充日期、格式与替代元数据。
本轮修复 09-20、09-21 记录的方案链接；09-17 边界修正记录末尾的 10-10 当前状态
追加移出历史正文，其字段删除事实由既有[清理方案](../../../doc/l3-dispatcher-planner/iteration/design-remove-unused-follow-reservation.md)
及迁移台账维护。原始实现选择与历史测试结论不改写。

补充的部分替代链分别限定为：09-17 VLA 几何执行被 09-20 站端航点执行替代；
09-20 的共享航点实现归属被 09-21 家族归属替代，近点成功与多腿完成规则被
10-09 结果收敛替代；09-17 的保持目标接口、09-21 家族执行器归属和 10-09
家族物理完成门被原生 action 决策替代；原生 action 的任务取消归属被 10-10
强制取消决策替代。各旧决策未涉及的结论仍保留其历史含义。

本轮不修改业务实现、工具集合、消息、参数默认值或生产能力准入规则。
结构脚本已编写但未运行；没有新增测试、构建、门禁或验收通过证据。
