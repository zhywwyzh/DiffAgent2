# 基础飞行动作契约

Status: implemented
Contract-ID: l3-dispatcher/flight-actions
Parent: specs/implemented/l3-dispatcher.spec.md

> 定义六个基础飞行能力的行为，交付边界为 EGO cmd 输出与起降命令转交。
> 线上信封归 `l3-l4-rpc` 契约，技能机制归现行技能契约，ROS 隔离归适配边界。

## 0. 本轮交付边界

当前验收后端为 EGO planner。dispatcher 到 planner 的链路以 `/setpoint_cmd` 输出为
交付边界，cmd 后续的飞控、电机及实机处理不属于本轮任务；起降命令只验证转交。
采用受控 odometry/cloud/执行反馈验证动作完成和原点生命周期，不把模拟输入当成
实机证据。旧版后端切换机制可保留为配置职责，其他后端需独立证明能力一致性。

## 1. 名称和参数

唯一注册名是下表的 `basic_flight.*`，技能实例的 name 与其完全一致。
不接受 `flight.*` 别名，不在 RPC 层注入业务默认值；参数不包含任务编号。
所有业务 schema 均为对象、禁止未知键；数值必须有限且不是布尔值。

| 工具 | 业务参数 | 物理含义 | 完成语义 | synchronous |
|---|---|---|---|---|
| `basic_flight.takeoff` | `{}` | 请求起飞到配置高度 | `forwarded` | true |
| `basic_flight.land` | `{}` | 请求在当前位置降落 | `forwarded` | true |
| `basic_flight.translate` | 必填 direction、distance_m；方向为 forward/backward/left/right，距离大于 0 | 按调用执行时的机体水平朝向平移指定米数 | `action_result` | false |
| `basic_flight.rotate` | 必填 yaw_delta_deg，有限数值 | 原地执行有符号累计偏航角，单位度，左正右负 | `action_result` | false |
| `basic_flight.return` | `{}` | 返回本飞行会话的起飞位置 | `action_result` | false |
| `basic_flight.emergency_stop` | `{}` | 停止当前执行，并请求制动后悬停 | `forwarded` | true |

- 六个技能均不依赖视觉感知门；需要位姿、飞控状态的动作必须另行检查完整、带时间戳
  且新鲜的状态快照。`requires_perception=false` 不表示无需定位或控制模式检查。
- rotate 不沿用旧版 `(-360,360]` 隐含参数限制，不对累计角取模冒充完成。
  大角度拆成方向一致的小角度目标，以连续解缠偏航与动作结果判定；0 度在确认有效
  当前姿态后可无动作完成。超出部署执行预算时明确失败，不截断为另一个角度。
- return 空参直接代表 origin，不补 target 字段；`target=previous` 为未知参数，
  返回上一位置不属于本轮公开能力。
- 调用、重放、抢占和急停均经过同一 owner 门；六工具都持有 `flight-exclusive` 槽。

## 2. 执行与终态

- 每个动作由对应技能负责领域判定，core 只按名调度；共享下行执行不识别工具名。
- 起降命令经 `/px4ctrl/takeoff_land`，停止信号沿用 `/command/emergency_stop`。
  航点与偏航目标由 dispatcher 经通用执行端口和 ROS 适配层直接下发 planner，
  不迁入 `/mission/task`、独立 mission_executive 包及其转换接口。实际输入、反馈、
  取消、停止及消息字段按执行缝契约核实，禁止旧入口兼容层与双写。
- `action_result` 是真实动作结果的完成语义，不表示必须使用 ROS action。planner/
  飞控反馈通过执行端口关联到当前动作；不得以发布成功代替下游执行结果。
- `forwarded` 成功仅在真实出站端口完成转交后产生；不证明起飞高度到达、着陆完成
  或实机已悬停。缺少出口、明确未就绪或发布失败不得成功。
- 后续动作不能把前一次起飞的 forwarded 当作“已飞稳”；必须检查实际飞行状态。
- `action_result` 成功需要下游成功结果及技能完成门；下游失败、超时、失联、位置
  过期、目标不可执行均产生失败，不得以固定等待时间或单纯位置缓存判成功。
- 成功结构化结果包含 `completion`，取本工具的元数据值。重复结果、旧代次结果
  和取消后的迟到结果不能生成新终态或推进当前动作。
- 同步技能在 on_start 中经端口执行并报告终态；异步技能经 plan_tick、动作武装、
  完成门与裁决推进。默认钩子可继承，无需为凑数量覆写空方法。

## 3. 原点与物理飞行会话

- 原点由独立会话服务拥有，含位置、坐标系、有效时间及飞行会话边界信息；不读取
  队列的上一任务快照充当起飞点，不使用 RPC 的诊断 session 字段识别物理会话。
- 在确认地面状态并准备起飞时采样候选原点；仅在真实起飞状态得到确认后提交为有效
  原点。起飞发布失败或未确认时不得将候选点用于返航。
- 已在空中的重复起飞请求不得覆盖原点。明确着陆结束当前会话；新起飞建立新会话。
  普通任务覆盖、调用取消或急停不抹除同次飞行的有效原点。
- 重启、仿真重置、坐标系重置或无法证明连续性的定位变化后使原点失效。当前提案不
  提供持久化恢复；空中重启后不能把当前位置补成起飞点。
- 无有效原点时 return 明确失败，不回退为当前位置、上一任务位置或上一会话原点。
- 返航到原点水平位置时采用经过约束校验的安全飞行高度，不自动降落；降落由 land
  独立请求。目标高度和到达阈值由部署配置给定并经测试冻结，不暗改起飞位置含义。
- 逐步历史返航与任务文本回退的保留依赖继续登记，不能因本轮不消费而删除。

## 4. 端口与分层

- 通用动作武装、实例归属、代次、结果暂存和唯一终态使用现有 SkillHost 语义。
  起降、停止、下游取消、飞行状态快照和原点读取采用显式能力端口，不访问宿主私有
  队列、ledger 或发布器。新增端口必须先在技能契约中采纳，不绕开端口白名单。
- ROS 文件只做消息转换和通信；规划器模式、航点塑形归调用技能，共享执行状态机
  与结果判定归执行缝领域模块。装配根构造对象、注入端口并持有 disposer，不承载流程。
- 动作武装绑定实际发布技能实例。停止或覆盖由 dispatcher 使旧代次失效，并经已有目标口下发保持意图覆盖旧 goal；只清空
  Python 队列不算取消物理执行。重注册同名技能不改变已发布动作的归属。
- 每次注册返回 disposer；反注册和进程停止释放资源，顺序与获取相反，异步释放等待完成。

## 5. 急停与恢复

- 目标为制动后悬停，不改为停桨、返航或自动降落。执行侧证明旧目标停止推进并输出
  制动/保持 cmd；本轮不验收 cmd 下游实机跟踪，不把 Empty 发布当作保持命令证据。
- 先验证实际 planner 的停止入口与 remap、轨迹跟踪及模式条件；只有有证据需要时才
  增设 hover goal，禁止两个停止目标相互覆盖。
- 定位不可用、重复急停、模式切换、重启与恢复条件必须明确并验证；无法证明可悬停时
  报告失败原因，不静默伪造飞行状态。
- 工具急停、租约丢失安全停共享执行侧停止能力，但租约丢失不伪造工具调用。
  普通取消/覆盖不得因复用清理路径而误发急停信号。

## 6. 交付判据

| 标识 | 判据 |
|---|---|
| BF1 | 六个名字、参数与静态声明逐项一致；旧 flight 名继续拒绝，return 只接受空参 |
| BF2 | 各真实出口存在，成功及故障路径完整；测试能力不进入生产集合 |
| BF3 | 位姿新鲜度、平移方向/单位、累计偏航、原点生命周期均有纯领域测试 |
| BF4 | 起降/急停 forwarded 与物理完成区分；三项异步动作使用真实结果与完成门 |
| BF5 | 抢占、取消、旧结果、同名重注册、资源逆操作及终态唯一通过 |
| BF6 | 急停停止轨迹与保持、起飞转交、平移、旋转、返航、降落转交有至 cmd 边界的受控集成证据 |
| BF7 | 完整实现与测试交付时同步更新工具集合和计算所得 revision，采纳叶并更新根表 |

## 7. planner 边界修正

只清理来源任务编号，保留 LocalGoalSet 的 yaw_low_speed、goal_to_follower。取消和
停止意图的构造属于 dispatcher 的共享执行职责，复用旧 stopMotion 的目标覆盖方式；
不新增 planner/cancel，不修改后端停止算法。验证记录见[边界修正决策](../architecture/2026-09-17-dispatcher-planner-boundary-correction.md)。
