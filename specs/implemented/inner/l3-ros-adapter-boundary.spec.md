# ROS 适配边界

Status: implemented

Contract-ID: l3-dispatcher/ros-adapter-boundary
Parent: specs/implemented/l3-dispatcher.spec.md

> 限定 ROS 通信与领域逻辑的分离方式。适用于 l3 全部 Python 与 C++ 代码。
> 既有 `mission_core`（非 ROS 领域核心）+ `mission_ports`（抽象出站端口）+
> `mission_fsm_ros`（ROS 适配器）三层是本契约的既有范例；本契约将该范例
> 提升为全局纪律。

## 1. 分层

```
适配层（*_ros.py / *_ros.h / *_ros.cpp / ros_adapter/）
    │ 实现端口、写入共享状态
    ▼
端口层（抽象接口：*_ports.h / SkillHost）
    │
    ▼
领域层（不含 ROS 类型的纯逻辑）
```

## 2. 规则

- **R1 收发集中**：`rospy` / `roscpp` 的 Subscriber、Publisher、Service、
  ActionClient、ActionServer 只能出现在适配层文件。领域层出现任一处即缺陷。
  `l3-dispatcher/core-boundary` B3 的四类通道（急停 / `if_handle_yaw` /
  任务相位 / 命令内容监控）是 core 的语义白名单，同样适用本规则：其 ROS
  实现落在适配层文件，core 只持有端口引用。
- **R2 无消息类型**：领域层不得 import 或声明 ROS 消息类型（`std_msgs`、
  `geometry_msgs`、`quadrotor_msgs` 等）；跨层数据以自有数据结构或端口参数
  传递。
- **R3 入站经两种途径**：
  - 协议：领域层声明端口接口，适配层实现并在回调中调用；
  - 内存：适配层把最新数据写入共享状态对象（如帧快照、状态存储），领域层
    直接读取，不感知数据来源。

  二者可并存于系统内；同一份数据只选一种，不得双写。
- **R4 出站经端口**：领域层的对外副作用（发布、调用服务、发送 goal）必须经
  端口方法；领域层不得直接 publish。
- **R5 适配层无决策**：适配层只做消息翻译、端口实现与参数装载；不得包含
  状态推进或业务判定。
- **R6 契约稳定**：更换传输（ROS1 / ROS2 / zenoh）或实现语言，不得改变主题
  名、服务名、action 名与消息字段名（与 `development-workflow/l3-coding-style`
  §6 行为契约一致）。

## 3. 共享状态

> 内存访问途径的规范；共享状态是适配器与领域层之间的数据面。

- **S1 单一写入方**：每份共享状态只有唯一写入方（通常是某个适配器）。
  领域层只读；领域层需要写回时必须经端口。
- **S2 完整性**：共享状态的写入必须是完整快照，不得出现半更新状态被读到。
- **S3 新鲜度可读**：共享状态必须携带时间戳或序号，领域层据此判新鲜度；
  过期数据的处置由领域层显式决定，不得默认使用旧值。
- **S4 不承载决策**：共享状态只承载数据，不承载状态推进或业务判定。

## 4. 跨语言边界

> 同一能力分置 Python 与 C++ 时的规范（经 pybind 或等价绑定）。

- **X1 绑定面即端口面**：跨语言暴露的函数集合等同于该能力的端口集合；
  不得把领域内部方法逐个暴露。
- **X2 大块进出**：跨语言调用以整块数据进出（数组、结构体、快照），禁止
  为单次小计算做逐元素往返。
- **X3 类型收敛**：跨语言边界使用自有数据结构，不直接传递框架消息类型。
- **X4 核心无框架依赖**：C++ 侧领域核心不依赖通信框架类型，以便单测与复用。

## 5. 收益

- 领域层可脱离 ROS 单测；
- C++ 领域核心可被 Python 侧复用；
- 传输可整体替换，不波及决策逻辑。

## 6. 门禁

| 门禁 | 检查 |
|------|------|
| G7 | 领域层文件零命中 `rospy\.` / `ros::` / `Publisher(` / `Subscriber(` / `SimpleActionClient`（R1） |
| G8 | 领域层的 import 闭包不含任何 `*_msgs` 包（R2） |
| G9 | 每个端口接口至少有一个适配层实现，且实现体内无状态推进分支（R5） |
