# 当前任务取消与紧急悬停优化方案

> 摘要：取消当前任务时立即使其指令失效、释放任务归属并请求紧急悬停；停止确认独立跟踪，建图、地图、定位和常驻通信继续运行。依据当前工作区的原生 action 实现与使用者明确要求。方案与源码调查已完成，当前已按本方案修改本地实现；运行验收仍待明确许可。

## 1. 背景与动机

使用者要求取消具有强制中断语义：例如站端停止按钮触发后，当前导航及其后续指令必须失效，并尽快执行紧急悬停。取消释放的是本次任务拥有的资源，不包括 现有规划器等常驻系统的地图与建图能力。

当前实现把任务归属和等待物理停稳绑定在同一活动记录中；普通取消未直接发送独立急停，停止执行又依赖定时器与规划锁。需要同时解决任务释放、停止优先级和常驻资源保护，不能仅更名 `cancel()` 或增加一次消息发布。

## 3. 目标与约束

- **目标**：合法取消被接收后，先阻止当前任务继续运动，立即尝试停止，独立完成任务清理及终态；停稳确认不再占用旧任务资源。
- **范围以当前任务为界**：取消当前调用及其派生指令；已准入的新调用、其他调用的历史终态和常驻服务不因旧取消而删除。
- **常驻资源保护**：保留地图、建图更新、定位、传感器订阅、控制心跳、悬停输出、通信端点、技能注册、有效返航原点。取消不调用节点关闭、地图重置或物理飞行会话 reset。
- **不做的事**：本轮不改 CoPaw 或外部设备控制系统、不新增通用 cancel RPC、不重构建图算法、不以停桨或自动降落代替悬停。
- **硬边界**：禁止新旧接口转接器；被替代语义直接删除；core 保持六态，设备停止状态归 execution；owner 与租约检查仍有效。
- **时效边界**：取消不排普通任务队列、不等待规划完成才阻止旧输出；不承诺未经测量的毫秒上界或零制动距离。状态缺失不能阻止导航失效和停止尝试，不能伪造位置生成有效悬停。

## 4. 方案决策

### 4.1 资源归属

| 资源 | 取消后的处理 |
|----|----|
| 当前调用、任务代次、待执行命令及技能多腿状态 | 立即标记取消并清理，派生发送全部失效 |
| 当前任务的 owner、宿主 action key、结果暂存 | 清除实例引用，不等待物理停止 |
| 当前导航目标、重规划结果、轨迹和偏航任务 | 作废执行代次，阻断旧结果提交与输出，再清理任务数据 |
| Action 协议句柄与取消回执 | 转交独立停止记录；只保留传输关联，不持有技能、任务载荷或目标列表 |
| 停止期限、停止确认、后端启动标识 | 归设备停止状态管理，超时后闭锁新运动 |
| 有界终态历史、租约、注册表、通信连接 | 保留正常生命周期，不因单任务取消整体释放 |
| 地图、建图、定位、传感器、返航原点 | 保留；不得作为取消清理目标 |

这里的“立即释放”是解除任务执行权及引用。正在计算的规划对象应以协作取消退出或待计算返回安全销毁，不从另一线程强制析构。其结果在停止标志设置后已无权提交。

### 4.2 停止入口与任务清理

内部取消、站端急停工具、同源覆盖、租约丢失共用停止执行能力，但保留各自调用终态与鉴权语义。

1. 准入层在短临界区内完成 owner／call 校验、取消标记与发送许可撤销；正常调用的发送提交点再次核对代次，覆盖“已取出队列尚未发出”的竞态。
2. 经装配注入的通用中断端口立即设置设备停止屏障并请求紧急悬停，不依赖普通调用消费者；不得在 runtime 锁内执行阻塞网络调用或技能钩子。
3. 独立尝试全局停止信号与指定 Action Cancel。任一路失败继续另一路，分别记录原因；尚未发送的 Goal 也要完成任务释放，不能以“无 handle”跳过全局停止。
4. 当前任务的清理使用短临界区及代次校验，技能清理异常不能阻止队列、owner、结果与账务释放；耗时钩子必须移出任务生命周期锁或支持协作中断。
5. 单次调用提交唯一 cancelled 终态；物理停止失败另报设备故障，不把旧调用再次终结，也不恢复其资源。

保留普通调用队列，取消不再向它阻塞 `put()`。停止通知按已有调用关联键去重；独立唤醒处理清理，首个停止信号不能等清理线程。急停工具的优先属性由装配注册通用中断入口，core 不新增工具名分支，tool_plane 不导入家族实现。

任务取消、技能注销和进程关闭拆开：注销已非 owner 的技能不能触发全局急停；首次普通任务启动时的初始化清理不应误发停止；关闭进程仍履行有限停止等待后注销端点的职责。

### 4.3 共享会话与设备停止状态

ActionSession 保留单个活动任务记录，新增无 owner 的停止记录；取消时将必要传输关联移交并清空任务记录。ROS 回调不能继续闭包捕获包含技能对象的 ActionKey：改用发送关联令牌，任务归属表在取消时删除。令牌只用于传输关联，不成为工具身份或新的业务编号。

设备状态为“可接纳／停止中／停止故障”，属于 execution，不能增加 core FSM 状态。停止中允许完成新调用准入与必要排队，但禁止发出新运动；停止故障需显式停止重试并获得可信确认后恢复。

旧回执仅更新对应停止记录，不能设置新任务结果。丢失 Action Result 时，以新鲜、同后端且属于本次停止之后的恢复代次与 ready/stop_confirmed 完成设备恢复；不能仅凭取消前缓存的 ready。重复请求合并，不重置停止期限。停止超时保留设备故障和有界诊断，清除不再需要的旧传输引用。

现有 Empty 急停没有请求关联且与 Action Cancel 跨通道，不能假设到达顺序。重复停止不得撤销已有停止确认前的保护；进入新任务前检查停止回执与状态基线，停止重试在确认后结束。若迟到全局急停仍到达，应安全中断当时运动并报告，不能以旧调用已释放为理由忽略真正的全局停止。若需要严格排除这种额外中断，须另行统一生产者并修订具有关联的停止协议，不能在本轮偷偷增加兼容桥。

### 4.4 planner 停止优先与输出保护

- 原生 Action Cancel 和急停回调都进入明确的 `request_stop`；取消仍只作用于匹配的活动 Goal，全局急停不要求存在 Goal。
- 独立回调队列／执行线程优先接收停止；以短锁或原子状态关闭当前导航的输出许可并递增执行代次。该动作不得争用长时间规划锁。
- 轨迹与 cmd 发布前检查执行代次及停止标志。规划线程返回后再次校验代次，过期结果不得覆盖保持输出；不能仅在规划开始时检查。
- 停止路径直接调用短时停止／保持能力，不等待 50 ms tick。cmd 输出保持正常控制节律；首次保持参考可用时立即提交，由唯一输出方发布，避免多线程同时写同一 cmd。
- 若算法本身无法立即中断，停止标志立即阻断其结果，计算随后退出或被丢弃；共享 planner 数据不能绕锁直接修改。地图更新不受导航停止标志控制。
- EGO／DIFF 在检查 odometry 前先使任务导航失效；保持参考可用性独立返回。SUPER 将任务清理命名为 `clear_navigation`，不经含混的全局 reset 入口；保持命令仍持续发布。
- 定时推进只用于停稳观测、有限重试和超时。重复停止不反复选取新悬停点、不重置偏航积分或延长期限。

后端 Action GoalHandle 可由服务端保留到协议终态，用于返回取消／失败及停止确认；该记录不授权继续规划或占有任务资源。启动保持与停止故障重试也走同一设备机制，恢复不重新发送旧目标。

### 4.5 目录与命名

沿用现有平面，不增加独立执行节点或泛化 services 层：

```text
dispatcher/
  core/                 # 调用与任务归属清理
  tool_plane/           # 合法取消与优先中断通知
  execution/            # action_session.py、ports.py、skill_host.py、composition.py
  ros_adapter/          # planner_action_ros.py、flight_commands_ros.py
planner/
  planner_execution/    # 停止状态和原生 action 接口
  <后端>/               # execution_backend 与已有轨迹/cmd 输出实现
```

| 类型 | 规范与拟用名称 |
|----|----|
| 取消当前任务 | Python `cancel_task`，必须有调用归属校验 |
| 请求设备停止 | Python/C++ `request_stop`，幂等；独立于任务对象 |
| 清理导航数据 | C++ `clear_navigation`，只清目标、轨迹和导航子状态 |
| 释放调用归属 | Python `release_call`，清引用，不注销技能 |
| 状态记录 | `StopRecord`，不包含 owner、技能实例或任务载荷 |
| ROS 收发实现 | 保持 `*_ros.py`、`*_ros.cpp`，领域逻辑不直接发布 |

旧接口处理：停止语义中的 `recover()` 删除并更新全部调用方；现有 `/planner/reset` 若保留，应明确只是导航停止／重置，不保留旧 C++ 方法别名。主题及 action 名本方案不改。

## 6. 删除清单

| 删除项 | 理由 |
|----|----|
| 普通取消“不触发急停”的规则与注释 | 被使用者明确的强制悬停语义替代 |
| 取消后继续保留任务 owner 到停稳的分支 | 任务资源和设备停止状态分离 |
| 取消命令向普通队列阻塞写入的路径 | 停止不能被常规指令队列阻挡 |
| 等待下一次 tick 才首次执行 backend.stop 的路径 | 缩短软件引入的停止延迟 |
| 停止入口 recover 的含混命名及旧别名 | 停止、任务清理与设备恢复职责明确 |
| 无定位时跳过导航失效的提前返回 | 不具备悬停参考仍必须阻断旧动作 |

不删除地图、建图线程、定位订阅、传感器缓存、控制心跳、有效原点、注册表或正常通信端点。

## 7. 实施步骤（P0/P1/... 分期）

### P0 — 契约与资源边界

### P1 — 优先取消与任务资源释放

- 范围：tool_plane、core、ActionSession、宿主及 ROS 客户端回调关联；装配注入中断端口。

### P2 — 原生停止与三个后端

- 范围：planner_execution、各后端停止实现、回调调度及轨迹/cmd 提交点；EGO/DIFF 的独立轨迹消费者一并追踪。
- 行为不变式：旧规划即使迟到也不能重新输出，保持持续运行，地图不被清理；后端能力缺失明确报告。
- 验收：获许可后覆盖长规划、定位失效、重复停止、cmd 收敛与建图连续性。
- 回退：后端与共享执行协议作为同一变更撤回，不保留旧接口转接器。

### P3 — 调用链与交付记录

- 范围：确认部署中 CoPaw 按钮真实请求、设备控制端的轨迹接收与停止行为；取得源码入口后按 owner 范围处理，当前不修改外部树。
- 行为不变式：本地 cmd 输出证据不能代替设备控制接管与设备停稳证据。
- 验收：只在明确许可及环境可用后执行；缺少外部链路证据时注明交付止于本地边界。
- 回退：不部署未经确认的外部停止协议；保留已完成任务清理及设备闭锁行为。

## 8. 验收标准

统一声明：本轮只做源码调查与方案生成，未运行或编写测试，不执行构建、语法检查或验证性门禁。以下为后续获得明确许可后的判据，不是已通过结果。

- [ ] 普通队列满或规划耗时时，停止接收与旧输出屏障仍能触发；分别记录接收、首个停止输出、停稳确认时间，不把 50 ms 定时周期当作端到端保证。
- [ ] 当前任务全部指令、owner、宿主 key、多腿状态已释放；注册表、地图、定位、返航原点与端点仍存在并工作。
- [ ] 任一停止发送失败、技能钩子异常或定位丢失，都不阻止另一停止路径与任务清理；设备不能伪报停止成功。
- [ ] 停止之后完成的旧规划、旧反馈、成功结果、队列命令不能推进任务或覆盖悬停。
- [ ] 每次合法取消只产生一个 cancelled 终态；重复取消不重置期限；旧取消不清除新调用数据。
- [ ] 停稳前禁止新运动；停止超时释放旧任务资源但保持设备故障；恢复不重放旧目标。
- [ ] EGO、DIFF、SUPER 停止期间建图输入与更新持续，地图不因取消重置，控制保持持续输出。
- [ ] CoPaw 请求类型及设备控制端行为取得实际证据后才声明按钮到设备闭环；未取得则保留明确缺口。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|----|----|----|
| 只把 cancel 放到高优先级队列 | 正在执行的长调用仍阻塞停止 | 首次停止经独立短路径，清理异步且代次守卫 |
| 只绕开规划锁直接修改共享对象 | 数据竞争与轨迹损坏 | 原子失效标志＋唯一输出仲裁，算法数据在原锁内安全清理 |
| 清空 owner 但回调仍捕获 ActionKey | 旧技能实例仍被引用 | 用不含 owner 的传输令牌，删除任务归属映射 |
| 全局 Empty 与 Action Cancel 乱序 | 迟到急停可能中断新任务 | 维护设备屏障、停止关联与有限重试，明确全局停止优先，不虚称跨通道顺序保证 |
| reset 范围未来扩大 | 误清地图或物理飞行会话 | 导航清理接口列出允许修改字段，取消不调用全局 reset |
| 所谓紧急停止只是零导数保持参考 | 实机制动效果未知 | 保留控制器约束，取得 cmd 与设备观测后评价；不承诺理论最短停止时间 |
| 外部跟踪器继续消费缓存轨迹 | l3 已停而设备仍运动 | P3 追踪真实轨迹消费者与输出仲裁，缺口不以本地发布成功掩盖 |

## 实施记录（2026-10-10）

P0–P2 已交付本地代码，P3 的外部链路仍缺源码及运行证据。未提交、未部署。

- `ToolRuntime` 在合法取消时立即标记并提交唯一取消终态，释放调用槽；中断通知不进入普通队列。普通队列满时拒绝普通指令，急停仍可通过独立入口。
- `ToolControlPlane` 首先调用注入的强制停止端口，再唤醒独立清理线程；移除普通队列中属于被取消调用的指令。技能数据在生命周期锁内安全清理，耗时计算退出前不强制析构；发送提交点依据取消标记拒绝旧任务。
- `ActionSession` 清理任务记录，以不含 owner 的 `StopRecord` 跟踪传输句柄、后端启动与停止期限。客户端 ROS 回调只捕获随机发送令牌；不捕获技能对象。停稳前阻止新运动，超时保留设备故障并丢弃旧传输句柄。
- 全局急停和指定 Action Cancel 独立尝试。出口失败不阻止另一出口；停止确认前有限重试，并且两个出口均未发出时急停工具不能返回 forwarded。重复请求不延长停止期限。
- 新增 `planner_execution/command_output_ros.h/.cpp`：短锁保护最终命令发送，独立状态订阅和保持定时器继续运行。服务端独立回调队列接收急停及取消，先使旧输出失效，再以 try-lock 尝试后端清理；规划锁忙时不等待它才关闭输出。
- `WaypointExecution::request_stop` 替代 recover；首次后端停止移到进入停止阶段时，tick 仅推进观测、重试和超时。停止开始时释放目标窗口；匹配的迟到取消可以收敛取消终态，不能重新开始动作。
- EGO 的轨迹采样改为有生命周期的线程并串行访问轨迹数据；原生 cmd 经输出仲裁，旧运动输出被拦截。普通导航的规范轨迹在动作接纳后提交，停止期间不交付旧运动规范轨迹。建图对象和输入不改动。
- SUPER 删除重复保持输出分支，保留原命令 topic 和控制增益，由统一输出仲裁发送；导航 reset 改为 clear_navigation，仅清目标和轨迹，保留地图及定位。取消不注销节点或端点。
- DIFF 的独立 `Apps/traj_server.cpp` 已定位并直接修改，增加原生输出仲裁及轨迹代次匹配；取消后拒绝和清理旧轨迹。它不能替代尚未取得的按钮至设备闭环证据。

### 实施中补充的接口决策

追踪到 DIFF 的独立跟踪进程后，为避免把规划器自报停止当作跟踪端已接管，新增原生保持回执：

| 接口 | 有意变更 | 目的 |
|----|----|----|
| `ExecutionState.msg` | 增加 execution_generation、motion_enabled | 明确输出许可与代次，跨进程丢弃旧运动 |
| `traj_utils/PolyTraj.msg` | 增加 execution_boot_id、execution_generation | 把 DIFF 轨迹绑定到原生动作的输出归属 |
| `quadrotor_msgs/CommandState.msg`、`/planner/command_state` | 新增 holding 回执 | DIFF 服务端等待同启动、同代次的新鲜保持输出确认 |

这些接口由原生生产者和消费者同时采用，没有旧接口转接层；涉及生成消息，部署时须同步重建依赖方。主题/action 的既有名称保持不变。

软件输出交付与设备实际制动分开：停止标志设置后的旧 cmd 不能再由本地仲裁器交付，已进入 ROS 队列或外部跟踪器缓存的命令仍受外部实现约束。现有全局 Empty 无请求关联，迟到的全局急停仍具有停止优先级，不能宣称跨 topic 严格顺序。没有运行证据时不承诺停止延迟、制动距离或外部控制器效果。
