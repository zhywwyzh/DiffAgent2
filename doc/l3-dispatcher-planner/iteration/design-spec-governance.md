## 3. 目标与约束

- **目标**：以 README 为唯一编写规则入口，提供根、叶、决策模板，整理现有契约和引用，提供只读检查脚本。
- **非目标**：不修改 l3 业务代码、消息、参数和运行协议；不以本轮文档整理证明能力已实现或已验收；不提交或推送。
- **硬边界**：禁止新增新旧接口转接器；被替代说明直接删除或迁入唯一过程归属，不留双份权威；保留工作区已有未提交内容。
- **许可**：未获测试与验收许可，不运行测试、语法检查、门禁、构建或运行验证，不读取测试文件。

## 4. 方案决策

- **目标目录树**：保持现有生命周期及 root/inner/architecture/process 层级；新增 `specs/tools/station-host-spec-lint.py`；模板直接置于 README，不新增模板 spec 子树。
- **命名规范表**：

  | 类型 | 规范 | 示例 |
  |------|------|------|
  | 根契约 | `<domain>.spec.md` | `topology.spec.md` |
  | 叶契约 | `inner/<area>-<name>.spec.md` | `inner/l3-core-boundary.spec.md` |
  | 决策记录 | `<类型>/yyyy-mm-dd-<topic>.md` | `process/2026-10-14-spec-governance.md` |
  | 静态检查入口 | `<实体>-<动作>.py` | `station-host-spec-lint.py` |

- **接口形态**：脚本仅以仓库位置为输入，读取 Markdown，输出错误与需人工审阅事项；退出码区分结构错误与结构通过，结构通过不代表语义或实现通过。
- **状态**：implemented 表示已采纳生效，不承诺实现或验收；proposed 表示未采纳；rejected 表示否决；archived 表示失效。未采纳设计留 proposed，交付进度留 doc。
- **模板**：根使用范围、不变量、Inner contracts、边界；叶使用范围与非目标、术语与身份、输入输出与配置、行为规则、失败取消与资源生命周期、归属与依赖、条款检查判据。保留旧条款数字与标识，避免破坏引用。
- **决策**：新记录完整使用模板；历史冻结记录保留原始正文，只追加归属明确的导航元数据。由本轮统一迁移删除误入历史的当前状态说明，记录处置理由，不伪造当时事实。
- **旧接口 → 删除**：删除“尚未迁移”作为当前新入口说明；不创建虚构旧脚本的兼容包装。

## 7. 实施步骤（P0/P1/... 分期）

### P0 — 规则闭合

- 范围：README 生命周期、模板、条款与变更流程。
- 行为不变式：业务协议不变；implemented 不被当作验收结论。
- 验收：待用户许可后按本文 §8 执行，本轮跳过。
- 回退：只撤回本轮治理说明，不覆盖已有工作区修改。

### P1 — 文档整理

- 范围：现有根叶契约、提案、历史引用及本轮决策。
- 行为不变式：保留 ID、原条款编号和业务要求；历史事实不重写。
- 验收：待许可后检查登记、链接、模板及业务字符串差异。
- 回退：逐项还原本轮文档迁移，保留原有未提交提案。

### P2 — 检查入口

- 范围：新增标准库 Python 只读脚本，说明能检查和不能证明的事项。
- 行为不变式：不修改文件、不访问网络、不安装钩子、不执行测试。
- 验收：待许可后运行结构检查并人工审阅语义；本轮不执行。
- 回退：移除新入口并同步移除 README 中对应声明，不留空包装。

## 8. 验收标准

> **统一声明**：除非使用者明确许可，否则跳过验收测试工作（`AGENTS.md` 硬性约束 §9）。本轮所有验证性检查均待许可。

- 待许可：运行 `python3 specs/tools/station-host-spec-lint.py`，记录结构问题和退出码。
- 待许可：人工确认生命周期、唯一归属、条款可判定性及跨契约一致性。
- 待许可：核对业务协议、参数、事件名和原有条款定位未因整理改变。
- 待许可：隐私检索；本轮不提交、不推送。
